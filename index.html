Ae 编程语言

Ae 是一种面向教学的、基于字节码的栈式虚拟机编程语言。它由编译器 aec、虚拟机 ae 和反汇编器 aed 三个独立工具组成，源码经编译后生成紧凑的二进制字节码，由虚拟机解释执行。

设计目标

Ae 的设计遵循以下原则：

  • 简洁性：语法最小化，核心关键字不超过 12 个，学习成本低。
  • 透明性：字节码格式完全公开，可直接阅读反汇编输出，便于理解编译原理。
  • 自包含：整个工具链以纯 C++ 实现，零第三方依赖，单文件源码即可编译。
  • 可扩展：模块化架构允许逐步添加语言特性，适合作为编译器课程的教学参考。

func isPrime(n) {

类型系统

Ae 是一种静态类型语言，变量在声明时必须显式标注类型。运行时采用类型化标签值（Tagged Value）模型，每个值携带类型标签，支持在运行时进行类型检查。

内置类型

Ae 提供四种内置数据类型：

类型 关键字 存储 说明
int int 64 位有符号整数 整数类型，支持算术与比较运算
double double 64 位 IEEE 754 浮点数 浮点数类型，支持浮点算术与比较
string string 引用计数的字符串对象 UTF-8 字符串，支持 + 拼接
bool bool 标签值（底层为 int） 布尔类型，字面量为 true / false

类型提升规则

当 int 与 double 在表达式中出现混合运算时，编译器自动将 int 提升为 double，结果类型为 double。该过程由 ITOD（0x0E）指令实现。

int a = 10
double b = 3.14
double c = a + b    // a 自动提升为 double, 结果为 13.14

比较运算的类型匹配

比较运算符（== != < <= > >=）在编译期根据操作数类型选择整型指令（IEQ/ILT/IGT...，0x10–0x15）或浮点指令（FCMP_EQ/FCMP_LT...，0x16–0x1B）：

  • 两侧均为 int → 生成整型比较指令
  • 任意一侧为 double → 生成浮点比较指令（必要时插入 ITOD）

字符串类型

字符串以双引号 " 或单引号 ' 界定，支持转义序列（如 \"、\\）。字符串拼接使用 + 运算符。

string s = "Hello, " + "World"  // "Hello, World"
string p = '单引号也可以'

变量与作用域

Ae 采用词法作用域（静态作用域）规则，变量的可见性在编译期确定。系统维护三个层级的作用域：

全局变量

在 main 块或函数外部直接赋值的变量为全局变量，存储在全局变量槽（Global Slots）中，通过 STORE（0x04）和 LOAD_VAR（0x05）指令访问。

main {
    x = 42       // 全局变量，自动分配 slot
    prln(x)     // 输出 42
}

局部变量

局部变量通过 local 关键字声明，仅存在于函数调用帧（Call Frame）中，通过 LOCAL_STORE（0x30）和 LOCAL_LOAD（0x31）指令访问。参数也被视为局部变量，位于局部变量区的前部。

func calc(a, b) {
    local sum = a + b      // 局部变量
    local prod = a * b     // 局部变量
    return sum + prod
}

作用域规则

  • 函数内部优先查找局部变量（含参数），未找到时回退到全局变量。
  • local 声明只能在函数体内使用，在函数外使用会触发编译错误。
  • 不同函数拥有独立的局部变量空间，互不影响。
  • 递归调用时，每次调用创建独立的调用帧，局部变量完全隔离。

复合赋值

Ae 支持复合赋值运算符 += -= *= /=，它们结合变量查找与算术运算：

x += 10    // 等价于 x = x + 10 (浮点加法 FADD)
count -= 1   // 等价于 count = count - 1

函数

函数是 Ae 的核心抽象机制。函数通过 func 关键字定义，支持参数传递、局部变量和递归调用。

函数定义

函数必须在 main 之外（源码顶部）定义，语法如下：

func name(param1, param2, ...) {
    local x = 10
    return x
}

规则

  • 函数名后紧跟参数列表（可为空），参数视为局部变量。
  • local 声明和参数共同构成局部变量区，按声明顺序分配 slot。
  • 支持递归调用——调用栈由 CallFrame 结构管理。
  • return 可返回任意类型的值；若函数体末尾无 return，编译器自动插入 return 0。
  • 用户自定义函数 ID 从 3 开始（0/1/2 保留给内置函数）。

函数调用

调用函数时，实参按从左到右的顺序求值并压栈，然后执行 CALL_FUNC（0x41）指令。虚拟机从栈顶弹出参数，创建新的调用帧（CallFrame），将参数写入局部变量区，然后跳转到函数入口。

递归示例

// 阶乘
func fact(n) {
    if (n <= 1) {
        return 1
    }
    return n * fact(n - 1)  // 递归调用
}

main {
    prln(fact(5))  // 输出 120
}

调用约定

步骤操作
1按从左到右顺序求值实参表达式，结果压入操作数栈
2执行 CALL_FUNC funcId argc
3VM 从栈顶弹出 argc 个值，写入新帧的局部变量区
4保存当前 PC 为返回地址，设置 currentLocals 指向新帧
5PC 跳转到函数入口，开始执行函数体
6遇到 RET（0x42）时，弹出帧，恢复返回地址
注意

调用参数数量必须与函数定义时的参数数量严格匹配，否则编译器会报告"参数数量不匹配"错误。

控制流

Ae 提供条件分支、循环和跳转控制语句，编译为 JZ（0x2A）和 JMP（0x2B）字节码指令。

if / else

if (condition) {
    // 条件为真时执行
} else {
    // 条件为假时执行
}

条件表达式的结果被压入栈顶，JZ 指令检查栈顶值是否为"假"（整数 0、浮点 0.0、空字符串或布尔 false），若是则跳转到 else 块或 if 之后的代码。

while 循环

while (condition) {
    // 循环体
}

编译后的结构：

  1. 循环条件前的位置记为 loopStart
  2. 求值条件，生成 JZ 占位（偏移待回填）
  3. 编译循环体
  4. 循环体末尾生成 JMP 跳回 loopStart
  5. 回填 JZ 的跳转目标为循环结束位置

break 与 continue

break 和 continue 用于在循环中进行跳转控制：

  • break：跳出当前循环，生成 JMP 占位，跳转目标在循环结束时回填。
  • continue：跳转到循环条件重新求值，生成 JMP 跳回 loopStart。
int i = 0
while (i < 100) {
    i = i + 1
    if (i % 7 == 0) {
        continue  // 跳过 7 的倍数
    }
    if (i > 50) {
        break      // 超过 50 退出循环
    }
    pr(i)
}
限制

break 和 continue 仅在 while 循环体内有效。嵌套循环时，它们仅作用于最内层循环。

运算符与表达式

Ae 的表达式语法遵循标准的运算符优先级规则，采用递归下降解析。

运算符优先级

从高到低排列：

优先级运算符结合性
1（最高）() 括号、- 一元负号左
2* / %左
3+ -左
4== != < <= > >=无
5（最低）= += -= *= /=右

算术运算符

运算符整型指令浮点指令说明
+IADD (0x06)FADD (0x0A)加法
-ISUB (0x07)FSUB (0x0B)减法

比较运算符

比较运算根据操作数类型生成不同的指令：

  • 整型：IEQ(0x10) INEQ(0x11) ILT(0x12) ILE(0x13) IGT(0x14) IGE(0x15)
  • 浮点：FCMP_EQ(0x16) FCMP_NE(0x17) FCMP_LT(0x18) FCMP_LE(0x19) FCMP_GT(0x1A) FCMP_GE(0x1B)

赋值与复合赋值

x = 10       // 简单赋值
x += 5      // x = x + 5  →  FADD
x -= 3      // x = x - 3  →  FSUB
x *= 2      // x = x * 2  →  FMUL
x /= 4      // x = x / 4  →  FDIV
错误处理

整数除法（IDIV）和取模（IMOD）在除数为零时，虚拟机会抛出运行时错误 整数除以零 或 取模除以零。浮点除法（FDIV）同样会在除数为零时报错。

内置函数

Ae 虚拟机内置三个函数，函数 ID 固定为 0、1、2，由编译器直接映射。

函数ID签名说明
pr 0 pr(args...) 打印所有参数，以空格分隔，不换行
prln 2 prln(args...) 打印所有参数，以空格分隔，末尾换行
inp 1 inp() → string 从标准输入读取一行，返回字符串

pr / prln

两者行为一致，区别在于 prln 在末尾附加换行。它们接受任意数量的参数，参数之间以空格分隔。值的输出格式如下：

  • string：直接输出字符串内容
  • bool：输出 true 或 false
  • double：若为整数值（如 3.0）则输出整数部分（3），否则输出完整浮点数
  • int：输出十进制整数

inp

inp() 从标准输入读取一行（不含换行符），返回 string。若遇到 EOF（文件结束），会抛出运行时错误。

pr("请输入你的名字: ")
string name = inp()
prln("你好, " + name)
调用约定

内置函数调用使用 CALL（0x02）指令，格式为 CALL funcId argc。与用户函数（CALL_FUNC）不同，内置函数的 ID 是硬编码的。语句级调用（返回值未被接收）会自动插入 POP（0x43）指令清除栈顶。

字节码文件格式

Ae 字节码文件（.aeo）采用二进制格式，大端字节序编码，整体结构分为文件头、常量池和代码段三部分。

文件头

文件头固定 16 字节，结构如下：

偏移大小字段说明
04magic魔数 "AeBc"（0x41 65 42 63）
41major主版本号（当前 1）
51minor次版本号（当前 0）
62flags标志位（当前保留为 0）
84constPoolCount常量池条目数（u32，大端）
124codeLength代码段字节数（u32，大端）

整体布局

文件头16 字节
常量池constPoolCount 条目
代码段codeLength 字节

常量池

常量池存储编译期确定的字面量（字符串、整数、浮点数），代码段通过索引引用池中的条目。常量池在文件中紧随文件头之后。

条目格式

每个常量池条目由三部分组成：

偏移大小字段说明
01tag类型标签
14length数据长度（u32，大端）
5lengthdata实际数据

类型标签

Tag 值常量类型数据编码
0x01UTF-8 字符串原始 UTF-8 字节序列
0x0232 位整数int32 补码（大端）
0x0364 位浮点数double IEEE 754（大端）

去重机制

编译器在添加常量时执行去重：相同值的常量只存储一次，后续引用复用同一索引。这有效减少了字节码文件的体积。

字节序说明

Ae 字节码统一使用大端（Big-Endian）编码，包括文件头中的 u16/u32 字段、常量池长度、以及所有指令操作数。这意味着同一份 .aeo 文件可在不同架构的处理器上正确执行。

指令集参考

Ae 虚拟机定义了 44 条字节码指令，涵盖栈操作、算术运算、比较、控制流、变量访问和函数调用。所有多字节操作数均采用大端编码。

跳转偏移编码

JZ（0x2A）和 JMP（0x2B）的操作数为 16 位有符号偏移量（int16），表示相对于跳转指令之后的位置的偏移。因此最大跳转范围为 ±32767 字节。编译器在生成跳转时使用"占位 + 回填"策略：先写入 0x0000 占位，待跳转目标确定后重写实际偏移。

跳转跨度限制

由于跳转偏移为 16 位有符号整数，单个跳转的最大跨度为 32767 字节。如果循环体或条件分支的代码量超过此限制，编译器会报错"跳转跨度过大（超出 int16）"。

编译器 (aec)

aec（Ae Compiler）将 .ae 源代码编译为 .aeo 字节码文件。

用法

aec <输入文件> [<输出文件>]

若未指定输出文件，默认将输入文件的扩展名替换为 .aeo（如 main.ae → main.aeo）。若不提供任何参数，编译器会交互式提示输入文件路径。

编译流程

  1. 词法分析（Lexer）：将源码字符流转换为 Token 流。支持 // 单行注释、双引号和单引号字符串、整数和浮点数、标识符及运算符。
  2. 语法分析（Parser）：采用递归下降法，按运算符优先级构建表达式。顶层处理函数定义（func）、main 块和全局语句。
  3. 代码生成：将 AST 转换为字节码指令序列。函数体独立缓冲，全局代码在前，函数定义在后。
  4. 链接：将所有函数定义追加到全局代码之后，末尾自动添加 HALT（0x03）。

函数定义布局

编译后，所有用户函数定义位于代码段的末尾（HALT 之前）。虚拟机启动时通过 preScanFunctions() 扫描所有 FUNC_DEF（0x40）指令建立函数表，因此函数可以在被调用之后才定义。

错误处理

编译器在语法分析阶段检测错误并输出描述性消息，例如：

✗ 编译错误: 语法错误: 期望 "{", 得到 'main'
✗ 编译错误: 未定义的函数: foo
✗ 编译错误: 函数 'bar' 参数数量不匹配: 期望 2, 得到 1
✗ 编译错误: local 只能在函数内使用

虚拟机 (ae)

ae（Ae VM）是 Ae 语言的运行时核心，负责加载字节码文件并解释执行。

用法

ae <字节码文件>

若不提供参数，虚拟机会交互式提示输入文件路径。支持引号包裹的路径（自动去除首尾引号）。

运行时结构

组件说明
操作数栈（Stack）执行指令时临时存储值
全局变量（Globals）全局变量槽数组，按需扩容
函数表（FuncDefs）函数 ID → 函数元数据的映射
调用栈（CallStack）调用帧（CallFrame）列表，支持递归
当前局部变量指向当前帧的局部变量区的指针

执行流程

  1. 加载 .aeo 文件，验证魔数 AeBc
  2. 解析文件头，读取常量池和代码段
  3. preScanFunctions()：扫描所有 FUNC_DEF 建立函数表
  4. 从 PC = 0 开始逐条执行指令，直至 HALT

值表示

运行时值采用类型化标签值（Tagged Value）模型：

enum ValueKind { VAL_INT=0, VAL_DOUBLE=1, VAL_STR=2, VAL_BOOL=3 }

struct Value {
    ValueKind kind
    union { int64 i; double f }    // 整数/浮点共用存储
    shared_ptr<string> str       // 字符串使用引用计数
}
运行时错误

以下情况会导致虚拟机抛出异常：魔数不匹配、文件过短、栈下溢、除以零、调用未定义的函数、在函数外使用局部变量指令、遇到未知指令等。错误信息以 ✗ 运行错误: 前缀输出。

反汇编器 (aed)

aed（Ae Disassembler）将 .aeo 字节码文件反汇编为可读的汇编格式文本，便于调试和分析编译产物。

用法

aed <字节码文件>

若不提供参数，反汇编器会交互式提示输入文件路径。

输出格式

输出分为三个部分：文件头信息、常量池和代码段。

; ╔══════════════════════════════════════════════════════════╗
; ║  Ae Bytecode Disassembly  (example.aeo)
; ╠══════════════════════════════════════════════════════════╣
; ║  Magic: AeBc  Version: 1.0
; ╚══════════════════════════════════════════════════════════╝
;
; ── Constant Pool (5 entries) ───────────────
  #  0  utf8   "Hello"
  #  1  int32  42
  #  2  double 3.14
; ── Code (68 bytes) ────────────────────────────
    0: LOAD_CONST  #0
    3: STORE      slot@0
    6: LOAD_VAR   slot@0

代码段格式

每行格式为：

  <偏移>: <助记符>  [<操作数>]  [; <注释>]

其中偏移是相对于代码段起始的字节偏移。内置函数调用显示函数名（如 CALL pr argc=1），函数调用显示 fid。

使用场景

反汇编器主要用于：验证编译器生成的字节码是否正确、调试运行时行为、学习字节码格式、分析程序性能瓶颈（指令数量）。
