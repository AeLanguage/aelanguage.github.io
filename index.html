核心特性

简洁而完整

编译到字节码

源码经编译器生成紧凑的 .aeo 字节码文件，魔数 AeBc，大端编码，含文件头、常量池与代码段。

栈式虚拟机

基于操作数栈执行，采用类型化标签值模型（Tagged Value），运行时区分 int / float / bool / null / string / table / func；表和函数是一等值。

类型系统

int 与 float 混合算术时自动提升为浮点；比较则要求两侧类型一致（1 == 1.0 会明确报错，要显式转换）。

AOT 编译

除了字节码，还能把 .ae 转译成 C++ 并编译成独立的可执行文件；编译器可链进 aec 本体，无需外部工具链。

反汇编工具

内置 aed 反汇编器，可将 .aeo 字节码反汇编为可读的汇编格式，便于调试与分析。

闭包与表

匿名函数 func(x){ … } 会捕获并共享外部变量，用来做回调与“有状态的对象”；表则同时充当数组、字典与记录。

从源码构建

Ae 的整个工具链仅依赖标准 C++ 库（C++17 及以上），无需任何第三方依赖。克隆仓库后，使用以下命令编译三个工具。若希望 aec --aot-exe 在进程内直接编出可执行文件，可额外安装 LLVM/Clang 套件后重新构建。

./aec -h

第一课：把 Ae 跑起来

这一课不假设你会任何编程语言。读完你能得到：装好工具链、写出第一个程序、知道怎么编译和运行、以及出错时该看什么。

完全没写过代码？先看这三句话

① 程序就是写给计算机的一串指令，它从上往下一条条执行。
② “变量”是一个有名字的盒子，你把值放进去，之后用名字取出来。
③ “函数”是一段可以反复用的指令，给它参数，它还你一个结果。
剩下的都是这三件事的排列组合。往下看，每一点都会配上能跑的例子。

Ae 是什么

Ae 是一门小而完整的编程语言。它没有庞大的框架，但该有的都有：类型、函数、闭包、表、模块、异常，以及一套标准库（文件、时间、路径、JSON、命令行、图形窗口）。

  • 编译成字节码：源码 .ae 由编译器 aec 编译成紧凑的二进制文件 .aeo，再由虚拟机 ae 执行。
  • 三个独立的小工具：aec（编译）、ae（运行）、aed（反汇编，想看编译结果时用）。
  • 纯 C++ 实现、零第三方依赖：整个工具链可以直接用 clang++ / g++ 编译出来。

装好工具链

官方发布的压缩包里就是三个可执行文件：aec、ae、aed（Windows 上是 aec.exe 等），解压后放进同一个目录即可。下载页里有 Windows / Linux / Android 的说明。

从源码自己编译（需要 C++17 编译器）：

$ clang++ -std=c++17 -O2 -Wall ..\Apt\aec.cpp -o aec.exe
$ clang++ -std=c++17 -O2 -Wall ..\Apt\ae.cpp ..\Apt\ae_main.cpp -o ae.exe
$ clang++ -std=c++17 -O2 -Wall ..\Apt\aed.cpp -o aed.exe

装好之后敲一次 ae --version，有输出就说明能用了。

第一个程序

新建一个文件 hello.ae，写三行：

// 我的第一个 Ae 程序
func main() {
    prln("你好，Ae！")
    prln(1 + 2 * 3)
}

prln 是“打印一行”的内置函数（print line）。// 开头的是注释，编译器会忽略。

编译并运行

$ aec hello.ae
[+] 编译成功: hello.aeo（387 字节）
$ ae hello.aeo
你好，Ae！
7

编译成功会生成同名的 .aeo，然后交给 ae 运行。默认输出文件名可以用 -o 改：

$ aec hello.ae -o build\hello.aeo

aed 文件.aeo反汇编（看编译器生成了什么）无

  • 给程序传参数：.aeo 之后的参数会原样交给程序（ae hello.aeo -h 时 -h 属于程序，不会被 ae 自己吃掉）。用 os.args() 或 args 库读取，见args一章。

程序从哪里开始跑

顶层语句先执行，然后如果定义了 main 函数，Ae 会自动调用它：

prln("顶层先跑")
func main() { prln("然后 main") }
// 输出:
// 顶层先跑
// 然后 main

所以两种写法都行：把代码写成 main（推荐，结构清楚），或者直接写在顶层（适合随手试两行）。

出错的时候

错分两类，看输出就能分辨。

编译期错误——代码没通过检查，根本没生成 .aeo：

$ aec broken.ae
[-] error[E1001]: 语法错误: 期望 )，得到 '}'
   --> broken.ae:3:1
      |
    3 | }
      | ^

运行期错误——编译过了，跑到某一步才失败：

$ ae broken.aeo
[-] error[E2003]: 表索引必须为正整数（1-based），得到 0
   --> broken.ae:4:12
      |
    4 |     prln(t[0])
      |            ^
      = stack (最近调用在前)
        main  broken.ae:4:12

读法：第一行是错误码 + 说明，--> 那行给文件:行:列，下面用 ^ 指出具体位置，最后的 = stack 是调用栈（谁调用了谁，最近的在最前）。详细的错误分类和含义见报错分区。

值与类型

Ae 的类型系统很小：六个类型，不多不少。这一课讲清每种值长什么样、怎么写字面量、怎么互相转换，以及什么情况下会直接报错。

六个类型

用内置函数 type() 就能问出一个值是什么类型：

类型名写法说明
int42、-7、0xFF64 位整数，范围 −9223372036854775808 ~ 9223372036854775807
float3.14、1.0、0.5双精度浮点。类型名是 float，不是 double
booltrue、false独立的类型，不等于 1 / 0
nullnull“什么都没有”，表示没有值

函数也是值，type() 会给你 func；详见闭包与函数值。

prln(type(1), type(1.5), type("a"), type(true), type(null))
// 输出: int float string bool null

数字

整数就是整数，浮点要写小数点。两者混合做算术会自动提升为浮点：

prln(7 / 2)        // 3   —— 整数除法会截断，不是 3.5
prln(7.0 / 2)      // 3.5
prln(1 + 1.5)      // 2.5
prln(7 % 3)        // 1   取余

整数是 64 位的，超出范围会回绕（不报错）：9223372036854775807 + 1 得到 -9223372036854775808。

真与假

判断条件时，下面这些值算“假”，其余都算“真”：

  • false
  • 0（整数 0 或浮点 0.0）
  • 空字符串 ""
  • 空表 {}
  • null
bool 不参与算术

true + 1 会直接报错；true == 1 是 false（bool 是独立类型）。要当数字用就显式转换：int(true) → 1。

转换

写法结果说明
int(3.9)3浮点转整数，截断小数部分
int("42")42字符串转整数，解析不了会报错
int(true)1bool 转整数
float(3)3.0整数转浮点
float("1.5")1.5字符串转浮点
str(42)"42"任何值转成文本（打日志最常用）

因为 + 只要有一边是字符串就会拼接，很多时候不用手写 str()：

local n = 3
prln("共 " + n + " 个")        // 共 3 个
prln(n + 1.5)                  // 4.5  两边都是数字，还是加法

比较：什么能比，什么不能比

  • 同类型之间随便比：数字比大小，字符串比字典序，bool 比 false < true。
  • int 与 float 混着比会报错（“不能直接比较 int 与 float”）。先统一类型：float(1) == 1.0。
  • 不同类型判等不报错，结果是 false：1 == "a" → false；true == 1 → false。
  • 和 null 比是合法的：x == null 用来判断“有没有值”。
  • 表按“是不是同一个表”比：内容一样但不是一个表，== 是 false（要内容比较用内置 equal()）。

完整的运算符清单见运算符与表达式；类型不匹配的报错细节见运行期错误。

变量与作用域

Ae 只有一条关于变量的硬规则：在函数里用变量之前先 local 声明。这一课讲清这条规则、块作用域、以及复合赋值和多变量赋值。

两种变量：局部与全局

local 声明一个局部变量：

local count = 0          // 声明 + 赋值
local name             // 只声明，值是 null
count += 1              // 之后直接用名字

不写 local 直接赋值会创建（或写入）一个全局变量——在顶层和函数里都一样：

func bump() {
    total += 1           // 全局 total（第一次用就创建出来）
}
func main() {
    local x = 1           // 局部：函数外看不见
    total = 0
    bump()  bump()
    prln(total, x)        // 2 1
}
读一个从来没声明过的变量会编译不过

prln(nope) 报 E1006 未声明的变量。反过来，写一个没声明过的名字是合法的（隐式创建全局）——这是 Ae 故意留的方便写法，但函数里建议一律 local，不然容易把全局改花。

块作用域

if / while / for 的花括号都是一个新作用域；在里面 local 的新变量出了块就没了，同名的会遮蔽外面那个：

local y = 2
if (true) {
    local y = 3            // 这是另一个 y
    prln(y)              // 3
}
prln(y)                  // 2

循环变量也是每轮独立的新绑定：for i = 1, 3 { local j = i } 里每轮的 j 互不影响——这一点在闭包里很关键（循环里建的闭包各自拿到那一轮的值）。

复合赋值

四个复合赋值运算符：+=、-=、*=、/=（没有 %=，取余要写 n = n % 3）。它们只对已存在的变量有效：

local n = 10
n += 5      // 15
n -= 3      // 12
n *= 2      // 24
n /= 5      // 4   整数除法：24/5 = 4
n = n % 3  // 1   取余要手写完整式子

一次声明多个

local 可以一次给多个变量赋值，右边个数要对得上：

local a, b = 1, 2
prln(a, b)              // 1 2

func minmax() { return 1, 9 }     // 返回两个值
local lo, hi = minmax()
prln(lo, hi)            // 1 9

函数一次返回多个值的写法（return a, b）见函数。

命名建议

  • 名字由字母、数字、下划线组成，不能以数字开头；区分大小写。
  • 不要用内置函数名做变量名：local len = 1 会报 E1009 遮蔽内建名。
  • 常量就用普通变量表示，Ae 没有单独的 const；约定全大写（local MAX = 100）表示“别改”。

运算符与表达式

算术、比较、逻辑、位运算、拼接、三元表达式——这一课给出完整清单和真实优先级，并标出几个和别的语言不一样的地方（整除截断、比较要求同类型、逻辑运算返回的是操作数本身）。

两个容易记错的点：** 比一元 - 还紧（-2 ** 2 = -4），<< 比 + 松（1 + 2 << 3 = 3 << 3 = 24）。不确定就加括号。

算术

prln(7 / 2)          // 3     整数除法截断
prln(7.0 / 2)        // 3.5   有一个是浮点就是浮点除法
prln(7 % 3, 2 ** 10)    // 1 1024
  • 除以 0 会报错（整数和浮点都是），不是得到 Infinity。
  • 整数溢出回绕，不报错。
  • bool 不参与算术：true + 1 报错，要写 int(true) + 1。

比较与判等

prln(1 < 2, 2 <= 2, 3 > 4, 1 == 1, 1 != 2)   // true true false true true
prln("a" < "b", "abc" == "abc")              // true true（字符串比字典序）
  • int 与 float 混着比会报错，先 float(...) / int(...) 统一类型。
  • 不同类型判等不报错、结果是 false（1 == "a" → false）。
  • 和 null 比较合法：x == null 判断“有没有值”。
  • 表按是不是同一个表判等；比内容用内置 equal(a, b)。

逻辑运算

and / or 会短路，而且返回的是操作数本身（不是强行变成 true/false），所以常用来给默认值：

local name = null
prln(name or "匿名")        // 匿名  —— name 是 null（假），所以取右边
prln(0 or "空")              // 空    —— 0 算假
prln(1 and "有")             // 有    —— 1 算真，所以取右边
prln(0 and "不会算")          // 0     —— 左边假就不看右边了
prln(not 1 == 2)              // true  —— not 比 == 松：等价于 not (1 == 2)

字符串拼接

+ 两侧只要有一边是字符串，就会把另一边转成文本再拼：

local n = 3
prln("共 " + n + " 个")     // 共 3 个
prln(n + 1.5)              // 4.5  两边都是数字 → 加法

三元表达式

local score = 72
prln(score >= 60 ? "及格" : "不及格")     // 及格

位运算

只对 int 有效，常用来做标志位：

prln(1 & 3, 5 | 2, 6 ^ 3, 1 << 4, 256 >> 2, ~0)   // 1 7 5 16 64 -1

判断与循环

条件必须写在括号里（Ae 不省略 ()）。这一课讲 if / while / do-while / for / 表遍历 / break / continue，以及“什么算真”。

if / else if / else

local score = 72
if (score >= 90) {
    prln("优")
} else if (score >= 60) {
    prln("及格")
} else {
    prln("不及格")
}

条件可以是任意值，按下面的“真假”规则判断；花括号不能省（哪怕只有一句）。

while 与 do-while

local i = 0
while (i < 3) {
    i += 1
}

local n = 0
do {                       // 先执行一次，再判断
    n += 1
} while (n < 3)

数值 for

写法是 for 变量 = 起点, 终点[, 步长]——用逗号，不是 to。步长可正可负，也可以是小数：

for i = 1, 5 { pr(i, "") }            // 1 2 3 4 5
for i = 5, 1, -1 { pr(i, "") }        // 5 4 3 2 1   倒着来
for i = 1, 9, 2 { pr(i, "") }         // 1 3 5 7 9
for f = 0.0, 1.0, 0.5 { pr(f, "") }   // 0.0 0.5 1.0

起点、终点、步长在进入循环时求值一次；循环变量是每轮全新的局部变量，出了循环就没了（外层同名变量不受影响）。

遍历表

for 键, 值 in 表 遍历所有键值对；只要一个变量就只拿值：

local t = {10, 20, name = "Ae"}
for k, v in t { prln(k, "=", v) }
// 1=10  2=20  name=Ae

for v in t { prln(v) }        // 只取值：10 20 Ae
  • 遍历顺序：数组段（1,2,3…）先按序号升序，然后是其它键；不要依赖非整数键的顺序。
  • 遍历是快照语义：开始遍历时先把键取出来，循环体里增删表不影响这一轮。
  • 要按顺序处理数组就用数值 for i = 1, len(t)。

break 与 continue

for i = 1, 10 {
    if (i == 3) { continue }     // 跳过这一轮
    if (i == 6) { break }        // 整个循环结束
    pr(i, "")
}
// 1 2 4 5

两者都只能用在循环里，用在别处会报 E1018。它们只作用于最内层循环。

什么算真

下面这些是“假”，其余都是“真”：

if (0) { }        // 假     整数 0 / 浮点 0.0
if ("") { }       // 假     空字符串
if ({}) { }       // 假     空表
if (null) { }     // 假
if (false) { }    // 假

所以 if (list) 之类“有内容才算真”的判断可以直接写，不用 len(list) > 0。

函数

函数用 func 定义，参数不用写类型，返回值用 return。这一课讲定义、调用、递归、多返回值，以及“函数也是值”这件事带来的用法。

定义与调用

func add(a, b) {
    return a + b
}

func greet(name) {
    prln("你好，" + name)
}

func main() {
    prln(add(1, 2))        // 3
    greet("世界")          // 你好，世界
}
  • 参数个数必须匹配，多一个少一个都是编译期错误（E1010）。
  • 没有 return 的函数返回 null。
  • 函数里看不到外面函数的局部变量；能看到的只有全局变量和参数（要“带走”外面变量就用闭包）。
  • 函数可以定义在函数里面（局部函数），也支持写在前面的函数调用写在后面的函数——定义顺序不影响调用。

递归

func fib(n) {
    if (n <= 1) { return n }
    return fib(n - 1) + fib(n - 2)
}
prln(fib(10))            // 55

递归深度有上限，默认 10000 层，超了报 E2006 调用栈溢出；用 ae --max-depth 200000 x.aeo 可以调大。

返回多个值

return 后面用逗号可以一次返回多个值，调用侧一次接住：

func minmax(a, b) {
    if (a < b) { return a, b }
    return b, a
}

local lo, hi = minmax(7, 3)
prln(lo, hi)             // 3 7

把函数当值用

用一个变量装住函数，就能像数字一样传参、放进表、从函数里返回——回调、策略表、分发都是这么写的：

local dbl = func(x) { return x * 2 }      // ★ 先装进变量

func apply(f, x) { return f(x) }     // f 是参数，也是个函数

func main() {
    prln(apply(dbl, 21))                // 42

    local ops = { inc = func(x) { return x + 1 }, dec = func(x) { return x - 1 } }
    prln(ops.inc(10), ops.dec(10))         // 11 9   表里存函数，用点号调用
}
具名函数不能直接当值传

顶层写的 func dbl(x) { … } 只能被调用：把名字写进参数位置（apply(dbl, 21)）会报 E1006 未声明的变量。要用函数值，就先装进变量或表：local dbl = func(x) { … }、local dbl = func name(x) { … }（后者名字可用于递归），再传 dbl。写回调时习惯用 func(e) { … } 就不会碰到这个问题。

func(x) { … } 是匿名函数（也叫 lambda / 闭包），它是 Ae 里最常用的“小块行为”，详细用法见闭包与函数值。

几个约定

  • main() 是可选的：定义了就会被自动调用（顶层语句先跑）。
  • 函数名不能重复定义（E1008），也不能和内置函数同名（E1009）。
  • 要提前结束就用 return；想主动报错用 error("说明")，见出错怎么办。
  • 短函数不必写文档串；Ae 没有注解、重载、默认参数——参数默认值用 f(a or 默认值) 这种写法代替。

闭包与函数值

匿名函数 func(x) { … } 会记住它出生时周围的变量——这就是闭包。它是 Ae 里做回调、工厂、状态封装的主要手段。

匿名函数

写在表达式位置、没有名字的函数：

local double = func(x) { return x * 2 }
prln(double(21))        // 42

常用在“当场给一个行为”的地方，比如事件回调：

sort(items, func(a, b) { return a.n < b.n })
顶层不能写匿名 func()

在文件顶层（函数外面）local f = func() { … } 会报 func 后需要函数名：顶层把 func 当成“函数声明”的开头。两个办法：写成 local f = func name() { … }（给它一个名字，递归也用它），或者放进 func main() { … } 里。函数体内匿名函数随便用。

捕获：闭包和外部共享同一个变量

闭包捕获的是变量本身（引用），不是当时的值快照。两边改都互相可见：

local n = 0
local inc = func() { n += 1  return n }
prln(inc(), inc(), n)        // 1 2 2   外面看到的 n 也变了

“计数器”就是这么来的——不需要类、不需要成员变量：

func counter() {
    local n = 0
    return func() { n += 1  return n }
}
local c1 = counter()
local c2 = counter()          // 各有一份 n
prln(c1(), c1(), c2())         // 1 2 1

工厂：用参数“定型”一个函数

func multiplier(k) {
    return func(x) { return x * k }
}
local triple = multiplier(3)
prln(triple(7))             // 21  —— k 是 3，被记住了

闭包可以活过创建它的函数：函数返回后，被用到的变量会被搬到堆上继续活着，所以不用担心“返回局部变量的引用”。

循环里的闭包

每轮循环的变量是独立的，所以循环里建的一批闭包各自记住自己那一轮的值：

local fs = {}
for i = 1, 3 {
    local j = i                 // 想留住这一轮的值就再声明一个局部变量
    fs[i] = func() { return j * 100 }
}
prln(fs[1](), fs[2](), fs[3]())   // 100 200 300

命名匿名函数（给递归用）

local fact = func f(n) { if (n <= 1) { return 1 }  return n * f(n - 1) }
prln(fact(5))              // 120

容易踩的坑

  • 闭包记得的是变量，不是值：如果外面之后改了它，闭包看到的是新值。
  • 调用一个不是函数的值会报运行期错误；传回调前可以先 if (type(f) == "func") 检查。
  • 大量小闭包没问题（都是堆上的小对象）；但别在每帧的循环里造几十万个闭包。

表

表是 Ae 里唯一的复合数据结构——数组、字典、记录、对象都是它。这一课讲清构造、读写、遍历和长度，尤其是 len() 的精确含义。

构造

local arr = {10, 20, 30}              // 数组：键是 1、2、3
local rec = {name = "Ae", ver = 2.1}    // 记录：键是字符串
local mix = {1, 2, tag = "x"}            // 混着写也行
local empty = {}                          // 空表
  • 键从 1 开始（不是 0）：arr[1] 是第一个元素。
  • 键可以是整数、字符串、bool；浮点不能当键（会报错，写 int(x)）。
  • 允许嵌套：{a = {1, 2}, b = {c = 3}}，取值 t.a[2]、t.b.c。

读写

local t = {10, 20, 30}
prln(t[1], t[3])          // 10 30
t[2] = 99                  // 改第 2 个
t[4] = 40                  // 写在末尾 → 追加

local r = {name = "Ae"}
prln(r.name, r["name"])   // Ae Ae   点号等价于用字符串键
r.ver = 2.1                 // 点号也能写

读不存在的键得到 null，不会报错——所以 if (t[k] == null) 是判断“有没有这个键”的常用写法。

长度：len 与 count 不是一回事

函数含义对 {10, 20, 30, name="Ae"}
len(t)数组段长度：从键 1 开始连续存在的个数3
count(t)所有键值对的数量4
删掉键 1 之后 len 会变成 0

delete(t, 1) 之后 len(t) 是 0——因为“连续”被打破了，不是数据丢了（t[2]、t[3] 都还在）。数组就老老实实当数组用：用 append 加、用 pop 从尾部取，别从中间删。

增删

local q = {1, 2}
append(q, 3)              // 追加到末尾 → {1, 2, 3}
prln(pop(q))              // 3   取出并删掉最后一个
insert(q, 1, 0)            // 在位置 1 插入 0 → {0, 1, 2}
delete(q, 1)              // 删掉键 1

遍历

for k, v in t { prln(k, v) }      // 键值都拿
for v in t { prln(v) }         // 只要值
for i = 1, len(t) { prln(t[i]) }  // 要保证顺序就用数值 for

复制与比较

local a = {1, 2, {3}}
local b = a                 // 同一个表（改了 a 就是改 b）
local c = copy(a)            // 浅拷贝：里面那个 {3} 还是同一个
local d = deepcopy(a)        // 深拷贝：整个套娃都是新的
prln(a == b, a == c, equal(a, c))   // true false true

当“对象”用

把数据和处理它的函数放进同一个表，就是最简单的“对象”：

func newCounter(start) {
    local self = {value = start}
    self.inc = func() { self.value += 1  return self.value }
    return self
}

local c = newCounter(10)
prln(c.inc(), c.inc(), c.value)   // 11 12 12

需要“私有字段”就用闭包：不放进表里的变量，外面就看不见。

字符串与文本

字符串按字符计数（一个中文算 1），可以从第 1 个字符开始取、可以切片查找替换，日常处理文本够用。

写字符串

local a = "你好，Ae"
local b = "换行\n制表\t引号\" 反斜杠\\"
local c = "a" + "b" + "c"            // 拼接用 +

支持的转义：\n（换行）、\t（制表）、\"（引号）、\\（反斜杠）。// 到行尾是注释，/* … */ 是块注释。

长度、下标与切片

local s = "中文测试"
prln(len(s))                 // 4      按字符数，不是字节数
prln(s[1], s[2])             // 中 文   下标从 1 开始
prln(substr(s, 2, 2))          // 文测   从第 2 个字符起取 2 个
prln(substr(s, 2, len(s) - 1))      // 文测试 想取到结尾就自己算长度
  • 下标和 substr 都是 1-based；substr(s, 起点, 长度) 三个参数都必须给（没有“取到结尾”的省略写法），越界会截断（substr("abc", 2, 99) → "bc"）。
  • 下标越界读出来是 null（不报错）；substr 越界则截断。
  • 下标只能是变量："abc"[1] 这种直接给字面量加下标编译不过，先 local s = "abc"。
  • 字符串不可变：所有“修改”都是产生新串。

local n = 3

字符串每次拼接都会生成新串。几千行的文本处理建议用表的 append 收集每行，最后 join(lines, "\n") 一次拼出来——参见内置函数一章的 append。

模块：写自己的库

imp 一行就能装进一个库。库分两种：工具链自带的（io / os / path，编译进可执行文件）和用 Ae 自己写的 .m 模块（json / args / math）——后者就是这一课要教你怎么写。

导入自带库

imp os
imp io

func main() {
    prln(os.platform(), os.cwd())
    prln(io.exists("a.txt"))
}
  • imp 写在文件顶部（函数外）。可以写多个。
  • 调用方式是 库名.函数名；内置函数（prln、len、str…）不用导入。
  • 用了没导入的库会报编译期错误 E1013；库文件找不到报 E1014。

写一个自己的模块

模块就是一个后缀叫 .m 的 Ae 文件，里面正常写函数。比如 mathx.m：

// mathx.m —— 我的小工具模块
func clamp(v, lo, hi) {
    if (v < lo) { return lo }
    if (v > hi) { return hi }
    return v
}

func sum(t) {
    local s = 0
    for v in t { s += v }
    return s
}

用的时候按文件名导入，函数挂在同名命名空间下：

imp mathx

func main() {
    prln(mathx.clamp(15, 0, 10))        // 10
    prln(mathx.sum({1, 2, 3}))        // 6
}

模块能找到哪里

imp 名字 会按顺序在这些地方找 名字.m（第一个找到的生效）：

  1. <工具链目录>/lib（自带库 json / args 就在这里）
  2. <工具链目录>
  3. <你的脚本所在目录>/lib
  4. <你的脚本所在目录>（自己的模块通常放这里）
  5. 当前工作目录下的 lib、以及当前工作目录
  6. 环境变量 AE_LIB_PATH 里列的目录（多个用 ; 或 : 分隔）

找不到时报 E1014 找不到库，并把找过的路径列出来——照着那份清单挪文件就行。

模块里可以做什么

  • 正常写函数：参数、返回值、多返回值、递归都一样。
  • 自己也能 imp 别的库（包括别的 .m 模块）。循环导入会被检测出来并报错。
  • 可以返回闭包，用来做“有状态的对象工厂”。
  • 模块里的全局变量是模块自己的，脚本里不会撞名（模块的函数名都挂在模块命名空间下）。
// stats.m —— 返回一个"累加器"闭包
func accumulator() {
    local total = 0
    return func(x) { total += x  return total }
}
imp stats
local acc = stats.accumulator()
prln(acc(3), acc(4))      // 3 7

几个注意点

  • .m 不能单独编译：它是给 imp 用的，编译入口必须是 .ae（aec mathx.m 会直接告诉你这件事）。
  • 模块是编译期摊进同一个程序的，所以没有 ABI 问题、也不损失性能——但改了模块要重新编译用到它的脚本。
  • 模块名就是文件名，所以名字里不要用减号之类的符号（imp my-mod 不是合法标识符）；mathx、myutil 这种就行。

出错怎么办

Ae 里“出错”分两层：写错了编译不过（改代码就行），跑起来才出的问题用 try / catch 兜住。这一课讲怎么捕获、怎么主动报错，以及什么时候不该用异常。

try / catch

try {
    local t = {1, 2}
    t[0] = 9                      // 键非法（表键从 1 开始）→ 报错
} catch (e) {
    prln("出错了:", e.code, e.kind, e.msg)
}
读和写不一样

读一个不存在的键不报错，得到 null（t[0]、t[5]、t["kk"] 都是 null）；写一个非法键才报 E2003。字符串下标越界读也是 null。

捕获到的是一个表，字段如下：

字段含义
e.code错误码，例如 "E2003"（详见运行期错误）
e.kind错误类别名，例如 "index"、"type"、"zero"
e.msg人能读的说明，就是报错那行文字
e.file / e.line / e.col出错的位置（文件、行、列）
e.stack调用栈（谁调的谁），字符串
 
try {
    prln(100 / 0)
} catch (e) {
    prln(e.code, e.kind, "第" + e.line + "行")
    prln(e.msg)
}

能被捕获的与不能的

  • 能捕获：运行期错误（类型不匹配、除零、索引非法、调用栈溢出）、标准库抛出的程序性错误、以及你自己 error() 抛的。
  • 不能捕获：编译期错误。语法写错、变量没声明、参数个数不对，这些在生成 .aeo 之前就失败了，程序根本没跑起来（它们属于编译期错误）。

主动报错：error 与 assert

func divide(a, b) {
    if (b == 0) {
        error("除数不能是 0")        // 抛出错误，信息自定
    }
    return a / b
}

assert(1 + 1 == 2, "数学崩了")       // 条件不成立就抛错，第二句是可选的说明
try {
    divide(1, 0)
} catch (e) {
    prln("自己的错误:", e.msg)       // 自己的错误: 除数不能是 0
}

在 catch 里想“继续往外抛”就用内置 raise(e)。

异常不是唯一的路：先看“预期失败”

“文件不存在”“环境变量没设置”这类本来就会发生的情况，标准库多数不抛异常，而是返回 null / false，再去问一句 库.lastError()。参数写错、id 非法这种程序 bug才直接抛。

imp io

local text = io.readFile("可能不存在.txt")
if (text == null) {
    prln("读不到:", io.lastError())    // 正常流程，不用 try
} else {
    prln(len(text))
}
该用哪个？

① 用户/环境导致、你能预料的失败 → 检查返回值，不要 try；
② 你自己代码里的“不应该发生” → error() 抛出去，让上层决定；
③ 需要在某个范围内“出了事也不崩” → try 包住那一段。

别把错误吞掉

catch (e) { } 空着什么也不做，是最容易埋雷的写法。至少要打出来：catch (e) { prln("警告:", e.msg) }；能处理就处理，不能处理就 raise(e) 继续往上报。

报错文本怎么读、每个错误码什么意思，见报错分区。

综合练习：写一个小工具

把前面学的串起来，写一个能用的命令行小工具：统计文本文件的字符数、行数、词数，把结果存成 JSON，并且对“文件不存在”“参数不对”都有像样的反应。

目标

$ aec wc.ae
$ ae wc.aeo notes.txt
文件: notes.txt
字符数: 128
行数: 6
词数: 21
已写入 notes.txt.json

涉及的东西：循环、表、字符串、函数（分别是 函数 与 闭包）、错误处理，以及三个标准库：args（解析参数）、io（读写文件）、json（存结果）。

// 统计一段文本
func analyze(text) {
    local lines = split(text, "\n")
    local words = 0
    for line in lines {
        for w in split(trim(line), " ") {
            if (len(trim(w)) > 0) { words += 1 }
        }
    }
    return {chars = len(text), lines = len(lines), words = words}
}

func spec() {
    return {
        {name = "json", short = "j", kind = "flag", help = "把结果打印成 JSON"},
        {name = "out",  short = "o", kind = "option", help = "结果另存到文件"},
    }
}

func main() {
    // ① 解析参数（parseArgv 用给定的参数数组，好写测试）
    local a = args.parseArgv(spec(), {"notes.txt"})
    if (a.error != null) {
        prln("参数有问题:", a.error)
        exit(2)
    }
    local path = a.rest[1]
    if (path == null) {
        prln("用法: wc <文件> [-j] [-o 输出]")
        exit(2)
    }

    // ② 读文件：预期失败用返回值判断，不用 try
    local text = io.readFile(path)
    if (text == null) {
        prln("读不了", path, ":", io.lastError())
        exit(1)
    }

    // ③ 统计并输出
    local r = analyze(text)
    r.file = path
    if (a.json) { prln(json.encodePretty(r)) }
    else {
        prln("文件: " + path)
        prln("字符数: " + r.chars + "\n行数: " + r.lines + "\n词数: " + r.words)
    }

    // ④ 存一份 JSON 报告
    local out = a.out or (path + ".json")
    if (!io.writeFile(out, json.encodePretty(r))) {
        prln("写不了", out, ":", io.lastError())
        exit(1)
    }
    prln("已写入 " + out)
}

这段代码里的几个决定

  • 统计逻辑单独一个函数（analyze）：输入文本、输出一个表，跟“读文件/打印”分开。这样想加“按段落统计”只改一个地方。
  • 参数用 args 库而不是自己读 os.args()：帮助文本、-o 文件、--out=文件 这些写法都是现成的。
  • 读文件不写 try：文件不存在是可预期的，io.readFile 返回 null + io.lastError() 就够了。
  • 退出码：参数错 2、读写出错 1、成功 0——别的脚本可以判断。
  • 结果表直接交给 json.encodePretty，字段名就是表的键。

自己动手加功能

  • 支持多个文件：for f in a.rest { … }，最后打印一行合计。
  • 加一个 --top N：统计出现最多的 N 个词（用表当计数器：count[word] = (count[word] or 0) + 1）。
  • 加 -r 递归处理目录：io.isDir + io.listDir（见 io）。
  • 给结果加时间戳：os.formatTime(os.time())（见 os）。
  • 用 json 把统计结果写成 JSON 文件，再用 imp 读回来核对——正好练习模块与文件读写。

这是 Ae 里最重要的一条设计约定：“本来就可能发生的事”和“写错了”分开处理。

标准输入

读键盘用内置 inp([提示])（见内置函数）：从标准输入读一行，读到结尾返回 null。所以“一直读直到结束”可以这么写：

while (true) {
    local line = inp()
    if (line == null) { break }      // 输入结束
    prln(len(line), line)
}

配合管道就是标准的“读标准输入”工具：ae wc.aeo < notes.txt。

三个容易踩的点

① 先判断再使用：readFile 可能返回 null，直接 len(它) 会报类型错误。
② listDir 给的是名字，要完整路径请自己 path.join(目录, 名字)。
③ readBytes 按字节切，中文可能被切一半——文本处理请用 readFile / readLines。

按扩展名筛文件

imp io
imp path

func filesWithExt(dir, want) {
    local out = {}
    local names = io.listDir(dir)
    if (names == null) { return out }          // 目录读不了就给空表
    for name in names {
        if (path.ext(name) == want) { append(out, path.join(dir, name)) }
    }
    return out
}

prln(filesWithExt(".", ".ae"))

要不要 toNative

  • io 库自己认两种分隔符，所以 path.join 出来的 / 路径直接能用。
  • 要把路径显示给用户、传给外部程序（或者写进日志给人看）时，用 path.toNative(p) 转成平台风格。
  • 反过来，用户输入的 \ 路径也能被 io 和 path 正常处理，不用手动换。
建议

程序内部一律用 path.join 拼、用 / 存；只在“边界”（打印、写配置给别的工具）上做一次 toNative。这样跨平台不会出岔子。

要小心的两点

① 坏的 JSON 会直接报错，不会返回 null

json.decode("{坏}") 抛出错误（E2008，栈里能看到 json._fail，说明是模块自己 error() 报的）。要“读配置读坏了也不崩”，请自己用 try 包住：
local cfg = null / try { cfg = json.decode(text) } catch (e) { prln("配置坏了:", e.msg) }

② 键会按字母排序，顺序不保留

json.encode 输出的键是排过序的（由 json.m 实现决定）。需要固定顺序就自己用表拼文本，或者接受排序。

args：命令行参数解析

imp args 之后，给一张“选项规格表”，就能得到 -o 文件、--out=文件、-v、-vv、位置参数、-- 分隔这些常见写法的解析结果，还能自动生成帮助文本。

先写规格表

local spec = {
    {name = "verbose", short = "v", kind = "flag",   help = "输出详细信息"},
    {name = "out",     short = "o", kind = "option", help = "输出文件", default = "out.txt"},
    {name = "level",   short = "l", kind = "count",  help = "详细级别（可重复）"},
    {name = "input",   short = "i", kind = "option", help = "输入目录（可多次）", multiple = true},
    {name = "must",                  kind = "option", help = "必填项", required = true},
}
字段说明
name长选项名（必填）：--out
short单字符短选项（可选）：-o
kind"flag"（开关，默认）｜"option"（取值）｜"count"（出现几次就是几）
help帮助文本（usage 用）
defaultoption 的默认值
required必填，缺了报错
multiple可重复出现，值收集到一张表里

函数一览

函数说明
args.parse(spec)用 os.args() 解析当前命令行（自动跳过程序名）。

math：数学函数

math 是用 Ae 自己写的模块（Apt/lib/math.m，不是 C++），共 69 个函数，覆盖三角、双曲、指数对数、幂、取整、组合、统计与随机。它不依赖任何外部库，imp math 即可使用。

导入与调用

prln(math.sin(math.pi() / 2))  // 1.0
prln(math.round(3.14159, 2))   // 3.14

常量一律写成函数调用形式（这是历史 API，保持兼容）：math.pi()、math.e()、math.tau()、math.sqrt2()、math.sqrt3()、math.phi()、math.ln2()、math.ln10()、math.log2e()、math.log10e()、math.epsilon()、math.huge()、math.nan()。

变参与默认参数

失败约定：返回 nan，不抛错

math 延续"数值函数不中断程序"的约定：定义域错误返回 nan（如 math.sqrt(-1.0)、math.log(0.0) 得 -inf），溢出返回 inf。结果能顺着算式传下去，需要时用 math.isNaN(v) 检查。

精度

按 IEEE-754 double 实现：sqrt / cbrt / floor / ceil 与 C 的 libm 逐位一致，其余函数误差 ≤ 4 ulp。|x| > 1e15 的三角函数结果不可信。另外 Ae 不允许 int 与 float 直接比较（E2001），math 内部一律先 float(x)，调用时也建议传浮点。

AOT：编译成可执行文件

除了默认的字节码路线，Ae 还能把 .ae 源码转译成 C++ 源码，再交给 C++ 编译器生成独立的可执行文件——不再需要 ae 虚拟机。这条路叫 AOT（Ahead-of-Time）。

两种用法

// 只生成 C++ 源码，自己拿去编
$ aec hello.ae --aot -o hello.cpp

// 一步到位：直接编出可执行文件
$ aec hello.ae --aot-exe -O2
[+] AOT 已生成可执行文件: hello
$ ./hello
Hello, World.

常用参数

参数作用
--aot生成 C++ 源码，不调用编译器
--aot-exe生成 C++ 并编出可执行文件
-O0..3优化级别（默认 -O2）
--cc=<命令>指定外部 C++ 编译器
--target=<三元组>交叉编译，如 x86_64-windows-gnu
--keep-obj保留中间 .o 文件（调试用）

需要外部编译器吗

--aot-exe 分三种情况：

环境行为
构建时链入了 Clang + LLD进程内编译，不需要任何外部编译器
没链入，但系统有 g++ / clang++自动调用外部编译器
都没有保留 .cpp，自行编译；也可用 --cc 指定

想让 aec 自带编译器（进程内编译、不依赖外部程序），先装 LLVM/Clang 套件再重新构建，构建脚本会自动探测 llvm-config：

$ pkg install clang llvm lld libllvm-static   # Termux / Debian
$ brew install llvm                          # macOS
$ ./build.sh                                 # 重新构建后 aec 即具备进程内编译能力

Windows 上 MSVC 不启用此功能，请用 clang++ 或 MinGW 的 g++。

已知限制

AOT 不支持协程（coroutine.*）与 run()：两者依赖切换调用栈，而 C++ 栈无法 unwind，遇到会在编译期报错。其余特性与字节码后端输出一致。

为什么能不依赖外部编译器

常规做法是由 aec 去调用一个外部编译器程序。但安卓上应用私有目录只能执行单个二进制，再 fork 出第二个程序会撞权限。所以 Ae 把 Clang 与 LLD 作为库链进了 aec 本体，"源码 → 目标文件 → 可执行文件"全程在自己进程内完成，做到全平台自包含。桌面端不受此限制，回退到系统编译器同样可用。

怎么读一条报错

Ae 的报错格式是固定的六件套：错误码、消息、文件:行:列、源码摘录、光标，还有可选的 help 与 stack。学会按顺序读，调试时间能少一大半。

逐行拆开

$ aec broken.ae
[-] error[E1006]: 未声明的变量 'pritn'（赋值可隐式创建全局；函数内请先用 local 声明）
    --> broken.ae:4:8
       |
     4 |     prln(pritn(1))
       |          ^^^^^
       = help: 赋值可以隐式创建全局变量；函数内请先用 local 声明。
部分意思
[-] error[E1006][-] 是错误（[+] 是成功提示，[!] 是警告）。方括号里是错误码——按码查表最快，见下面三页
未声明的变量 'pritn'…一句话说明发生了什么，通常已经包含关键线索（这里是“名字拼错了”）
--> broken.ae:4:8文件、行号、列号（按 1 起）。列号按显示宽度算：中文算 2 列，和你编辑器状态栏里看到的一致
源码摘录 + ^^^^^出错那一行，下面的 ^ 精确指到出问题的词（长度就是那个词的长度）
= help:怎么改。多数常见错误都有一句
= stack (最近调用在前)只有运行期错误有：谁调用了谁，最上面一行是出错的位置，最后一行 <script> 是顶层语句

运行期错误长什么样

$ ae crash.aeo
[-] error[E2002]: 整数除以零
    --> crash.ae:2:16
       |
     2 |     return x / 0
       |                ^
     = stack (最近调用在前)
       c  crash.ae:2:16
       b  crash.ae:5:15
       a  crash.ae:8:15
       main  crash.ae:11:14
       <script>  crash.ae:10:13
  • 先看栈的最上面三行：出错函数、它被谁调用、再上一层。<script> 是自动生成的顶层代码，它那一行就是“哪条顶层语句引发了这一切”。
  • 栈里每一帧的行列号格式和主诊断一样，点的是“这一层当前停在哪”。
  • 运行期的位置来自指令而不是字符：有时候光标会落在表达式的末尾（比如 / 0 的 0 上），而不是运算符正中。位置是“这一段代码出错”，不必纠结一个字符。

查错的三步套路

① 看错误码定位大类 → ② 看消息里的名字（变量名？函数名？文件名？）→ ③ 顺着 ^ 看那一行的那个词。九成的报错到第二步就明白了：拼错的名字、少写的 imp、类型没统一、参数个数不对。

编译期错误（E1xxx）

编译期错误意味着 aec 没产出 .aeo，程序一行都没跑。aec 一次只报第一个错：改掉再编译，才会看到下一个。这一页按错误码把常见情形列全，每条都配真实输出。

先记住三件事

  • 拼错的名字最容易被抓到——因为 Ae 要求“先有赋值再读”，所以 pritn(x) 这种手误会直接报 E1006，而不会安静地变成 null。
  • 类型要自己统一：1 == 1.0 在编译期就会拦下来，让你显式写 float(x) 或 1.0。
  • 库要显式导入：用了 imp 才有库函数可调，忘了写通常先撞上 E1006 未声明的变量 'io'，而不是“未导入的库”。

$ ae mix.aeo

    --> mix.ae:2:15

源文件编码不对（GBK）：

$ aec gbk.ae
[-] error[E1017]: 源码不是合法 UTF-8（请把源文件保存为 UTF-8 编码）

Windows 上用记事本/某些编辑器默认存 GBK 就会这样。VS Code、Notepad++ 里选 “UTF-8” 另存即可（不要 UTF-8 with BOM，也没必要）。

两个容易误会的地方

① aec 一次只报一个错——不是只有一处错，而是先解决当前这个。
② .m 文件不能单独编译：aec mod.m 会报 [-] error[E0001]: .m 是模块文件（由 imp 使用），不能直接编译；程序入口请用 .ae。改模块的正确做法是编译用到它的那个 .ae。

运行期错误（E2xxx）

运行期错误是程序已经跑起来之后才发生的：.aeo 编译得很好，但执行到某一行时出了问题。它们全都带调用栈，能直接看到“谁调用了谁”。

完整输出示例

$ ae trace.aeo
[-] error[E2002]: 整数除以零
    --> trace.ae:2:16
       |
     2 |     return x / 0
       |                ^
     = stack (最近调用在前)
       c  trace.ae:2:16
       b  trace.ae:5:15
       a  trace.ae:8:15
       main  trace.ae:11:14
       <script>  trace.ae:10:13

栈里最上面那一行就是出错的位置，往下是调用它的地方。<script> 是自动生成的顶层代码（顶层语句都装在里面）。

怎么定位

  • 看栈第 2、3 行：出错函数是被哪个函数、用哪一行调用的。参数传错、数据没准备好，往往在上一层。
  • 类型错（E2001）先在最近的一行找“没统一的类型”：整数和浮点不能比、bool 不能参与算术——写 float(x) 或 int(x) 说清楚。
  • 除零（E2002）先看分母是不是算出来的 0：len(t) 空表、find() 没找到返回的都是 0 之类。
  • 下标错（E2003）看键的“种类”：表只认 int/string 键，t[1.5] 不行；字符串索引从 1 开始且必须是 int。
  • E2009 是库在告诉你参数不对：消息里通常已经把可用值列出来了（线帽、光标、渐变、trim 都是这样）。
  • E2006 先找递归的出口：忘记写终止条件最常见；调试时也可以 ae --max-depth 20 x.aeo 让它早点停下来，栈短一点更好看。
运行期的“位置”是近似值

编译期错误的光标精确到词；运行期错误的位置来自正在执行的那条指令，有时会落在表达式的末尾（比如 x / 0 的 0 上）。看到行号对、列号略有偏差是正常的——它表示“这一小段代码出错”。

下一个问题：能接住吗？

能。try { … } catch (e) { … } 可以接住上面所有 E2xxx（exit(n) 除外），拿到 e.code、e.msg、e.stack 等信息——见处理与调试的套路。

库的报错与 lastError

标准库把失败分成两类，界线很清楚：能预料到的失败（文件不存在、环境变量没设、窗口建不出来）返回 null/false，原因放在 <库>.lastError()；写错代码（参数类型不对、值不合法、名字不存在）直接抛运行错误 E2009。

两类失败对照

预期失败 → 返回值 + lastError程序性错误 → 抛 E2009
典型情形文件/目录不存在、环境变量没设、图片打不开、窗口尺寸为 0参数类型不对（os.sleep("x")）、值不在取值范围内（path.join(1, "a")）
你要写什么检查返回值，需要时再读 lastError()不用检查——它会中断程序，除非你用 try/catch
什么时候发生和环境/用户输入有关，程序没毛病代码写错了，改代码就能修
 
imp io
imp os

func main() {
    // ① 预期失败：返回值是 null，原因在 lastError
    local t = io.readFile("肯定不存在.txt")
    prln("返回 =", t, "| 原因 =", io.lastError())
    // 返回 = null | 原因 = 无法打开 肯定不存在.txt: 系统找不到指定的文件。

    local v = os.getEnv("这个变量不存在")
    prln(v, "|", os.lastError())
    // null | 环境变量未设置: 这个变量不存在

    // ② 程序性错误：当场中断（E2009），消息里会告诉你为什么 + 可用值
    // os.sleep("x")   → [-] error[E2009]: sleep 的第 1 个参数需要 int
}

每个库都记着自己的 lastError

库是各自独立的，io.lastError() 和 os.lastError() 互不干扰，各自记录自己最近一次的失败原因。哪些函数走这条路：

库返回 null/false 的常见函数
ioreadFile writeFile appendFile readLines listDir mkdir remove copyFile rename open readBytes write seek
osgetEnv setEnv chdir cwd homeDir hostname formatTime
pathabs（拿不到当前目录时才失败；其余都是纯字符串运算，不会失败）
jsondecode decodeFile（文本不是合法 JSON）
json不走这条路：解析失败会抛错（E2008），因为它属于“数据坏了，无法继续”
lastError 不是状态，是“最近一次失败的原因”

它不会因为你后来成功了一次就保证变成空串：io / os / path 只有在新的失败时才更新。所以正确的读法是——先判断返回值，失败了再去读 lastError() 看原因：

local t = io.readFile(p)
if (t == null) {
    prln("读不了 " + p + "：" + io.lastError())
    return 1
}

库的“参数个数”错属于编译期

把库函数的名字写错、参数个数写错，aec 在编译时就拦下来了（E1011/E1012），根本轮不到运行期：

$ aec a.ae
[-] error[E1011]: 库函数 readFile 至少需要 1 个参数，实际给了 0
[-] error[E1012]: 库 'io' 里没有函数 'noSuchFn'

所以运行期见到的 E2009 基本都是值或类型的问题：os.sleep("x")、path.join(1, "a")… 这类消息通常已经把可用值列出来了，照着改就行。

自己写的库（.m 模块）怎么报错

Ae 模块就是普通 Ae 代码，所以两种手段都能用：

// mathx.m —— 自己的模块
func divide(a, b) {
    if (b == 0) { error("mathx.divide: 除数不能是 0") }   // 抛错：调用方必须处理
    return a / b
}
func parseCount(s) {
    local n = int(s)
    if (n < 0) { return null }        // 返回 null：让调用方判断
    return n
}

给模块定一套一致的原则就行：环境/用户输入的问题返回 null，编程错误用 error() 抛——和标准库同一套逻辑，用你模块的人不用重新学。

处理与调试的套路

知道错误码之后，剩下的是两件事：能接住的接住（try/catch），接不住的早发现（assert/error/返回值检查）。这一页把 Ae 提供的手段和实际写法放在一起。

try / catch：接住运行期错误

try {
    local t = {a = 1}
    prln(t.a.b)              // 对 int 取字段 → E2003
} catch (e) {
    prln("出错了:", e.code, e.msg)
}
  • 括号是必须的：catch (e)。只写 try { } 不给 catch 会报语法错误 E1001 语法错误: 期望 catch。
  • 能接住所有运行期错误（E2001–E2011），包括库抛出的 E2009、assert、error()。
  • 接不住 exit(n)——它是“结束程序”的指令，不是错误。
  • 出错点的信息在“出错现场”捕获：catch 里的 e.line 指的是出错那一行，不是 catch 这一行。

e 里有什么

字段例子说明
e.code"E2002"错误码字符串；拿它做分支最稳
e.kind"divzero"分类名：type divzero index bytecode stackoverflow assert user native arity input internal
e.msg"整数除以零"人看的消息（和终端上打印的一致）

try {
    prln(1 / 0)
} catch (e) {
    prln("code = " + e.code + " | kind = " + e.kind)   // code = E2002 | kind = divzero
    prln("位置 = " + e.file + ":" + e.line + ":" + e.col)
    prln("栈:", e.stack)
}

三个“主动报错/中断”的入口

写法码用途
error("消息")E2008直接抛错、终止（除非被 catch）。给“到这一步就不能继续了”用
assert(条件, "消息")E2007条件不成立就抛错，消息可选。给“这个前提必须成立”用
exit(码)—正常结束并带上退出码（默认 0）；catch 接不住
 
func divide(a, b) {
    if (b == 0) { error("divide: 除数不能是 0") }
    return a / b
}
func area(w, h) {
    assert(w > 0 and h > 0, "宽高必须为正")
    return w * h
}

重新抛出：raise(e)

想“记一笔再往外传”，把 catch 到的 e 交给 raise 即可——码、消息、位置都会原样带上（它接表，所以整个 e 都能传）：

func loadConfig(path) {
    try {
        return io.readFile(path)
    } catch (e) {
        prln("[日志] 读配置失败: " + e.msg)
        raise(e)          // 交给上层处理，信息不丢
    }
}

调试的四招

  • 分段打印：prln("① 到这里", x) 是最有效的手段。Ae 不用编译选项也能打印，改一行重编译很快。
  • 二分注释：把可疑的一段用 /* … */ 括掉，看错误还在不在——用它定位“是谁写的脏数据”。
  • 先查返回值再看 lastError：库的预期失败返回 null/false，不查就会在后面某处变成“对 null 做加法”这种绕远的错误。
  • 用 assert 把假设写下来：assert(len(rows) > 0, "空表不该走到这里")。程序会在最早、最清楚的地方停下，而不是在后面报一个莫名奇妙的 E2003。
  • 拿不准中间值：直接 prln("x=", x) 打出来最快，或者用 type(x) 确认类型；比翻日志直观得多。
常见坑清单

① 1 == 1.0 不行——两边类型要写成一样（float(x) 或 1.0）。
② 7 / 2 是 3（整数除法），要小数请写 7.0 / 2。
③ 字符串索引、substr 的起点都从 1 开始，不是 0。
④ 表的键不能是 float；t[1.5] 会报 E2003，用 int(x) 或 str(x) 说清键类型。
⑤ 忘记 imp 时先看到的是 E1006 未声明的变量 'io'，别去改 readFile。
⑥ 回调（事件、定时器）里出错会当场中断并打印栈，不会被静默吞掉——这是有意的。

顺序建议

写完一小段就编译一次（aec x.ae）——编译期错误最便宜；跑起来之后用 assert 和返回值检查兜住“不可能发生”的情况；真正和外界的交互（文件、参数、网络）用 try/catch 收口，并在 catch 里打印 e.code 与 e.stack，方便下次一眼定位。
